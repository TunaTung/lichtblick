## 0. 上位机定位（先读，决定所有设计取舍）

- **这是服务答辩的展示品，不是产品**。目标是：一个深色科技风单页仪表盘，数据看起来详细、酷，让评委觉得厉害，就够了。

### 1.2 上行帧清单（14 种，全格式）

所有帧第一个字段是 `"m":"帧名"`。

| 帧 | 周期 | 格式 | 字段说明 |
|---|---|---|---|
| `info` | 每次连上（含重连） | `{"m":"info","fw":"901w1","up":ms,"rst":0x..}` | 固件版本 / 上电时长 / 复位原因 |
| `st` | 5s | `{"m":"st","wifi":1,"up":..,"rc":..,"hb":..,"dp":..,"sm":..,"lp":..,"lpmax":..}` | `rc`=进入透传次数(重连) `hb`=心跳成功 `dp`=意外掉线 `sm`=ESP状态机枚举 `lp`=主循环频率 Hz `lpmax`=窗口内最慢单圈 us。★**电源验收判据：dp/rc 冻结 + hb 线性增长 = 供电稳定** |
| `bat` | 2s | `{"m":"bat","v":12.00,"low":0}` | ★**分压电阻未接，PC3 悬空，恒 12.00 占位（不是 bug）**；电阻(4:1，如30k/10k)接上即出真值，固件零改动 |
| `uw` | 200ms | `{"m":"uw","d":..,"a":..,"x":..,"y":..,"ok":..,"fc":..,"err":..,"gl":..}` | UWB 滤波值：`d`=距离 m `a`=角度 ° `x/y`=坐标 m `ok`=滤波就绪 `fc`=有效帧数 `err`=串口错 `gl`=野值剔除数（fc 持续增长 = 链路健康） |
| `fw` | 200ms | `{"m":"fw","st":..,"tv":..,"d":..,"a":..,"vx":..,"vy":..,"wz":..}` | 跟随状态机：`st`: 0=IDLE 1=STOPPED 2=HOLDING 3=APPROACHING 4=LOST 5=SEARCHING；`tv`=标签可见 `d`=跟距 m `a`=角度 ° `vx/vy/wz`=算法速度指令 (m/s, m/s, rad/s)。目标距离 0.6m、角度死区 10°。**SCAN 模式下不更新（显示最后一次跟随值，别当实时）** |
| `ch` | 500ms | `{"m":"ch","ex":[vx,vy,wz],"fb":[vx,vy,wz],"r":[4轮],"p":[4轮]}` | `ex`=期望速度 `fb`=编码器反馈速度（同序 vx m/s, vy m/s, wz rad/s）；`r`=四轮 RPM（取整）`p`=四轮 PWM 占空比；**轮序 [右前, 左前, 右后, 左后]**（motor.h `MOTOR_RF,LF,RR,LR`）。ex vs fb 曲线 = PID 调参 |
| `us` | ~1s/轮 | `{"m":"us","d1":..,"d2":..,"d3":..}` | 超声波 3 路距离 cm，无回波=0 |
| `la` | 500ms | `{"m":"la","s":2,"fc":54,"err":0,"d":[36个值]}` | 雷达摘要：`s`: 0=IDLE 1=INIT 2=SCANNING 3=ERROR；`fc`=圈数（增长=雷达在转）`err`=串口错；`d`=每 10° 一点共 36 点，**单位 cm，无效点=-1** |
| `imu` | 500ms | `{"m":"imu","r":..,"p":..,"y":..,"gx":..,"gy":..,"gz":..,"ax":..,"ay":..,"az":..,"t":..}` | `r/p`=横滚/俯仰 ° `y`=偏航 ° `gx/gy/gz`=角速度 °/s `ax/ay/az`=原始加速度 g `t`=温度 °C |
| `pose` | 1s | `{"m":"pose","x":..,"y":..,"yaw":..,"td":..,"sl":..,"vx":..}` | 融合位姿：`x/y`=编码器积分 m（**无电池供电时恒 0**）`yaw`=IMU 偏航 ° `td`=总行驶里程 m `sl`=打滑比 0~1 `vx`=车体前向速度 m/s |
| `dg` | 10s | `{"m":"dg","c":[22个计数]}` | 链路诊断计数，顺序 = diag.h DiagEvent 0..21（逐项见表 1.3） |
| `vi` | 变化时 | `{"m":"vi","i":2}` | OpenMV 物品识别号 |
| `mode` | 变化时 | `{"m":"mode","v":1}` | 1=FOLLOW 2=SCAN |
| `echo` | 收到下行时 | `{"m":"echo","rx":"$w"}` | 下行回声诊断（收到的每一行） |

### 1.3 dg 帧 22 个计数的含义（diag.h DiagEvent 顺序 0..21）

| # | 枚举 | 含义 |
|---|---|---|
| 0 | DIAG_DSP_Q_RX | 屏发 `$q`（进跟随） |
| 1 | DIAG_DSP_QMINUS_RX | 屏发 `$q-`（退跟随） |
| 2 | DIAG_DSP_W_RX | 屏发 `$w`（进扫描） |
| 3 | DIAG_DSP_WMINUS_RX | 屏发 `$w-`（关扫描） |
| 4 | DIAG_DSP_Q_TX | `$q\n` 回显给屏 |
| 5 | DIAG_DSP_QMINUS_TX | `$q-\n` 回显给屏 |
| 6 | DIAG_DSP_W_TX | `$w\n` 回显给屏 |
| 7 | DIAG_DSP_WMINUS_TX | `$w-\n` 回显给屏 |
| 8 | DIAG_DSP_OK_TX | `$ok\n` 发给屏 |
| 9 | DIAG_DSP_NONE_TX | `$none\n` 发给屏 |
| 10 | DIAG_DSP_ITEM_TX | 物品帧发给屏 |
| 11 | DIAG_DSP_RX_ERR | 屏串口 USART1 RX 错误 |
| 12 | DIAG_OMV_W_TX | `$w\n` 发给 OpenMV（开扫） |
| 13 | DIAG_OMV_Q_TX | `$q\n` 发给 OpenMV（停扫） |
| 14 | DIAG_OMV_LINE | 收到 OpenMV 完整行 |
| 15 | DIAG_OMV_OK | 解析出有效物品号 |
| 16 | DIAG_OMV_NONE | 收到 `$none` |
| 17 | DIAG_OMV_BAD | 未识别行 |
| 18 | DIAG_OMV_RX_ERR | OpenMV 串口 USART3 RX 错误 |
| 19 | DIAG_PC_ITEM_TX | 物品帧发往 PC (UART8) |
| 20 | DIAG_DIAG_TX | `$DIAG` 行发往 PC |
| 21 | — | （枚举到 DIAG_EVT_MAX 为 22 槽位） |

### 1.4 下行指令（4 条，已实测回环）

| 指令 | 效果 | 上报回执 |
|---|---|---|
| `$q` | 跟随 ON（UWB 跟随恢复，OpenMV 关） | `echo` + `{"m":"mode","v":1}` |
| `$q-` | 跟随 OFF（急停，OpenMV 不动） | `echo`（mode 无变化不发 mode 帧） |
| `$w` | 扫描 ON（急停 + OpenMV 开扫） | `echo` + `{"m":"mode","v":2}` |
| `$w-` | 扫描 OFF（OpenMV 待机） | `echo` |

注入路径：WiFi 下行 → `wifi_link_on_data()` → `Display_InjectLine()` → 与屏按键**同一命令队列** → `Mode_Update()` 消费。发出后 1 秒内回 echo。

### 1.5 链路层的坑（新会话必读）

- **电池供电时 ESP-01S 的 3.3V 掉电重启**：TCP 会话每 30~90 秒无声轮换，服务器只见 CLOSE、留下半开僵尸连接。纯 ST-Link 供电完全稳定。**稳压底座（独立 3.3V 专供 ESP）到货后此问题应消失——验收方法就是看 st 帧 dp/rc 冻结 + hb 线性增长**。
- 重烧固件后 ESP 残留透传会刷 "AT" 文本：已有 `+++` 自救（约 10s 自愈）；不恢复就整车断电 5s 或重启 TCP 服务器。
- `bat` 恒 12.00 是占位值不是故障（分压电阻未接）。
- SCAN 模式下 `fw` 帧显示的是最后一次跟随值。
- 帧里所有小数是浮点直接 `%.2f` 输出，没有CRC/序号——后端按行解析、坏行丢弃即可（echo 帧除外，它带任意文本）。
- 服务器日志 `server_log.txt` 里全是历史真帧，**做前端时可以写一个 log 重放器，不需要真车在场**。

## 2. 未来 WiFi 可能能得到的东西（按 答辩价值/改动量 排序）

1. **电池电压真值** —— 硬件到货（2 颗电阻 4:1 分压，电池正极→PC3）即得，**固件零改动**。`bat` 帧自动出真值 → 仪表盘电压表 + 低电告警。最高性价比。
2. **VFH 避障可视化** —— VFH 避障当前是"初始化了但没启用"的死模块（`VFH_Init` 被调、`VFH_Task` 全工程零调用、`vfh_result` 恒零）。把 `VFH_Task` 接进主循环 + `wifi_link.c` 加一帧（方向直方图/选定避让方向）→ 雷达图上叠加避障扇区，答辩效果好。改动量：main.c 一行调用 + wifi_link.c ~20 行。
3. **UWB 装车** —— `uw/fw/pose` 立刻变成真实跟随轨迹（跟随一人走的数据流），无固件改动，纯硬件动作。
4. **OpenMV 视觉扩展（下一战场）** —— `vi` 帧现在只有识别号；若 OpenMV 端报类别名/置信度，可扩成 `{"m":"vi","i":2,"n":"bottle"}` → 购物清单/识别历史面板。
5. **下行参数在线调（可选）** —— 命令队列已打通（与屏共用），可加如 `$d0.8`（设跟随目标距离）之类的解析（~10 行），答辩时"现场调参数"有演示效果。
6. **不建议**：雷达全点云（36 点摘要已是 WiFi 带宽合理上限）；ESP 端 RSSI（透传态拿不到，查一次要退透传，破坏链路）。
